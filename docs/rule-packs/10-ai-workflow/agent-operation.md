# Работа агента

## Старт

1. Прочитать `AGENTS.md`, `docs/index.md` и применимые rule packs.
2. Проверить branch, `HEAD`, `git status --short` и последние коммиты.
3. Найти живой план/README системы и доказательства текущего поведения.
4. Если задача многосоставная — сначала применить `planning.md`.

## Поток задачи

- Новейшее сообщение пользователя имеет приоритет.
- Не менять несвязанные файлы и не маскировать чужие ошибки.
- Сначала определить владельца состояния и публичный контракт, затем UI.
- Предпочитать вертикальный срез: ввод → изменение RGBA → история/сохранение →
  видимый результат.
- Новую идею вне активного среза записать в `docs/project/idea-inbox.md`.
- После каждого этапа синхронизировать `Resume Here`, roadmap и проверки.

## Перед завершением

1. Проверить task-owned diff и `git diff --check`.
2. Запустить минимальный достаточный gate из `validation-policy.md`.
3. Зафиксировать проверку и риски в плане.
4. Следовать Git-процессу из `AGENTS.md`.

## После сжатия контекста

Не доверять памяти или checkbox. Выполнить
`docs/project/context-recovery.md`, сверить записанный checkpoint с текущими
`HEAD`, status, кодом и тестами.
