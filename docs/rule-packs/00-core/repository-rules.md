# Правила репозитория

## Размер и форма модулей

- Код, CSS и конфигурация: максимум 150 строк на файл.
- Обычная документация: максимум 250 строк. Главы долгих планов в
  `docs/tutorials/` могут быть длиннее, но всё равно разделяются по смыслу.
- Одна ответственность на модуль. Нельзя уплотнять несколько statements в
  строку ради лимита.
- Имена файлов и каталогов — английские, явные, без `utils`/`misc`/`manager`
  для несвязанных обязанностей.

## Данные продукта

- RGBA-слой, документ, brush preset и viewport имеют типизированные контракты.
- Пресеты, пределы, тайминги и хоткеи хранятся как данные в `src/config`.
- Бинарные кисти и их metadata не смешиваются с runtime-логикой.
- Персистентная схема версионируется; миграция отделена от чтения текущего
  формата. Повреждённая запись не должна блокировать остальные документы.

## Границы

- `logic` не импортирует DOM, Canvas, storage или глобальный state.
- `core` владеет контрактами, bus, документом, history и инфраструктурой.
- Каждая `system` владеет одним процессом и не импортирует другую system.
- `ui` читает serializable view models и отправляет команды.
- `platform` изолирует File System Access, PWA и будущие desktop API.

## Пользовательская поверхность

- Все видимые строки — i18n keys с ru/en регистрацией.
- Все цвета, размеры UI, радиусы и анимации — theme tokens.
- Touch, pen и mouse поддерживаются явно; жест не должен делать недоступной
  команду на другом типе устройства.
- Ошибка необязательной кисти, импорта или сохранения изолируется и объясняется
  локализованным сообщением.

## Запрещено

- Возвращать `grid[y][x]` как модель полноцветного документа.
- Выдавать наличие файла кисти за доказательство её runtime-использования.
- Добавлять прямые system-to-system imports.
- Хардкодить UI-текст, hotkey или продуктовый лимит внутри обработчика.
- Переписывать несвязанные пользовательские файлы.
