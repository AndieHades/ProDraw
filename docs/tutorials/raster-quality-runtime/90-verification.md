# Verification

## Обязательный гейт этапа

Каждый этап доказывается минимальным достаточным набором из
`docs/project/validation-policy.md`, но `Q2B`, `Q4`, `Q6i` и `Q7` требуют
полного набора:

```bash
npm run check && npx eslint . && npm test && npm run validate && npm run build
```

Сдача выполняется отдельно и не заменяется тестами:

```bash
npm run package:mac
```

## Регрессионные бюджеты

Числа берутся из `docs/project/performance-budgets.md`. Baseline пересчитывается
в `Q0` на текущем macOS-хосте и фиксируется вместе с моделью процессора.

| Метрика | Требование после `Q2B` |
| --- | --- |
| ход пера, кисть 64 px, один интерполированный сегмент | не хуже четверти бюджета |
| тёплый composite p95 | в бюджете |
| холодный composite заполненного A4 | в бюджете |
| сэмпл → готовая frame model p95 | в бюджете |
| глубина Undo на `1920×1080` | не меньше `50` шагов |
| байты слоя `1920×1080`, заполненного целиком | не больше учетверённой площади плюс накладные тайлов |

Перф-набор запускается в один worker и не смешивается с функциональными
тестами: иначе он измеряет конкуренцию runner, а не runtime.

## Проверка сохранённого поведения `RQ-PAR-01`

Для каждой строки нужны три доказательства: положительное, отказное и
persistence.

| Строка | Положительное | Отказное | Persistence |
| --- | --- | --- | --- |
| PSD импорт | структура слоёв, папок, масок и эффектов | повреждённый файл даёт сообщение | повторное открытие совпадает |
| PSD экспорт и перезапись | запись в исходный путь | занятый файл не рапортует успех | round-trip |
| PNG экспорт холста, слоя, дерева | размеры и альфа | превышение бюджета пикселей отклоняется | файлы на диске |
| Галерея и восстановление | список и открытие | повреждённая запись не блокирует остальные | две generation |
| Слои и вложенные папки | порядок, видимость, обтравка | лимит слоёв | сохранение и Undo |
| Выделение и плавающий фрагмент | перенос содержимого | пустое выделение | Undo |
| Трансформация | один resample на Apply | отмена возвращает исходник | Undo |
| Crop и Trim | обе команды | пустой результат | Undo |
| Текстовые слои | правка и растеризация | пустой текст | Undo |
| Анимация и таймлайн | кадры и позиция | пустой таймлайн | сохранение |
| Tile Mode | бесшовный повтор и заворот | выключение | сохранение |
| Отражение документа | порядок и метаданные слоёв | — | PSD и PNG |
| Палитра, пипетка, reference | выбор и захват цвета | отсутствующий источник | сохранение |
| Глобальный Pan | средняя кнопка и Space | во время трансформации | — |

## Ручные проверки

Автоматизировать нельзя и они называются явно:

1. Ход пера на планшете: непрерывность, нажим, наклон, ластик пера (`Q3`, `Q4`).
2. Качество штриха пресет-кистью в сравнении с ожиданием пользователя (`Q4`).
3. Приёмка собранного `/Applications/ProDraw.app` пользователем на каждом
   этапе, помеченном как принятый.

## Правила отчёта

Пропущенная проверка называется точным именем и причиной. Красный гейт не
объявляется зелёным. Изменение решения сначала отражается в плане, затем в
коде.
