## Evidence

The worktree was clean before the audit. `npm run validate` passed: TypeScript,
ESLint, 128 retained legacy tests, 41 TypeScript tests, documentation, line and
architecture fixtures, cycle/desktop/raster-entry validators and Vite build.
Green gates therefore describe the tested subset; they do not negate the gaps
below.

Confirmed foundations worth retaining:

- production starts at `src/main.ts` and uses strict TypeScript target modules;
- the authoritative image is lazy 256×256 RGBA tiles, not a pixel grid;
- viewport zoom/rotation are matrix-only and do not rewrite source pixels;
- pressure, tilt, coalesced Pointer Events, per-brush stabilization, basic
  Smudge, requested canvas presets and physical brush-set folders exist;
- the exact future two-column tool order and excluded Procreate sections are
  already recorded.

## P0: blocks safe daily drawing

### `SAFE-01` — current work can be lost

`AutosaveSystem` delays a fire-and-forget full save by 700 ms, while
`DocumentRepository` owns only one `current` record. New Canvas replaces the
document and clears history immediately; Electron closes without a renderer
flush handshake. A quick close can lose the final stroke, and a new canvas can
replace the only recoverable work.

Evidence: [`AutosaveSystem.ts`](../../../src/systems/autosave/AutosaveSystem.ts),
[`DocumentRepository.ts`](../../../src/core/persistence/DocumentRepository.ts),
[`RasterEditorApp.ts`](../../../src/app/RasterEditorApp.ts),
[`electron-main.mjs`](../../../desktop/electron-main.mjs).

### `PERF-01` — document presentation recomputes everything

Every requested frame scans every populated visible-layer tile, clones tile
bytes, performs object-heavy per-pixel compositing, creates a temporary canvas
and `ImageData` for every tile, and does no viewport culling. A filled A4 has
about 140 tiles before multiplying work by layer count. This cannot sustain pen
latency on realistic A4/4K artwork.

Evidence: [`CanvasPresenter.ts`](../../../src/ui/canvas/CanvasPresenter.ts),
[`compositeTiles.ts`](../../../src/core/document/compositeTiles.ts).

### `PERF-02` — Brush and Smudge run synchronously in the input callback

Every dab scans its pixel bounds on the renderer thread; Smudge scans them once
to pick pigment and again to write it. Coalesced events are processed in one
synchronous loop. Large brush sizes can perform millions of pixel iterations
before the next event or frame.

Evidence: [`DrawingSystem.ts`](../../../src/systems/drawing/DrawingSystem.ts),
[`renderBrushDab.ts`](../../../src/core/brush/renderBrushDab.ts),
[`renderSmudgeDab.ts`](../../../src/core/brush/renderSmudgeDab.ts).

### `MEM-01` — history has no byte budget and retains old documents

History limits entries to 100 rather than bytes. Each tile patch owns `before`
and `after`; a broad operation may therefore retain tens of MiB per step.
`clear()` leaves the surface registry intact, so every New Canvas keeps the old
document surfaces reachable for the process lifetime.

Evidence: [`TileHistory.ts`](../../../src/core/history/TileHistory.ts),
[`RasterEdit.ts`](../../../src/core/history/RasterEdit.ts).

### `BRH-01` — bundled `.brush` files are approximations

All 12 archives contain `Brush.archive`, but runtime ignores it and reads only
root `Shape.png`/`Grain.png`. Only 3 archives expose that root shape and 5 expose
that root grain; the rest use manually authored profiles and procedural
fallbacks. The existing Lineart test explicitly expects a shape fallback.

Evidence: [`bundledBrushes.ts`](../../../src/config/bundledBrushes.ts),
[`procreateBrush.ts`](../../../src/core/brush/procreateBrush.ts),
[`bundledBrushes.test.ts`](../../../tests/brush/bundledBrushes.test.ts).

### `BRH-02` — many visible Studio controls are no-ops

Spacing/lateral/linear jitter, falloff, taper, shape angle/roundness, grain
scale, tilt-to-size and min/max size appear and persist, but the stroke path and
dab renderer do not consume them. Preview cards and Drawing Pad use a bare
`BrushPreset`, so decoded shape/grain maps and the document path can disagree.

Evidence: [`brushStudio.ts`](../../../src/config/brushStudio.ts),
[`StrokePipeline.ts`](../../../src/logic/stroke/StrokePipeline.ts),
[`renderBrushPreview.ts`](../../../src/ui/brushes/renderBrushPreview.ts),
[`BrushStudioPad.ts`](../../../src/ui/brushes/BrushStudioPad.ts).

## P1: required foundation before more tools

### Input and image quality

- `INP-01`: touch currently paints; there is no two-finger pan/zoom/rotate,
  pen-versus-touch arbitration or palm rejection.
- `INP-02`: drawing has no `lostpointercapture`, window blur or visibility
  cleanup, so a driver/focus interruption can leave the stroke session stuck.
- `STB-01`: stabilization uses fixed alpha per event, so the same gesture at
  60/120/240 Hz produces different filtering; the raw endpoint can create a
  straight lift tail. No recorded Huion trace proves otherwise.
- `SMG-01`: straight-alpha colour interpolation can make dark translucent
  halos; Smudge has no selection/mask clipping and only one exposed strength.

Evidence: [`DrawingSystem.ts`](../../../src/systems/drawing/DrawingSystem.ts),
[`ViewportSystem.ts`](../../../src/systems/viewport/ViewportSystem.ts),
[`StrokeStabilizer.ts`](../../../src/logic/stroke/StrokeStabilizer.ts),
[`colorComposite.ts`](../../../src/logic/raster/colorComposite.ts).

### Documents, layers and files

- `DOC-01`: production layers are flat and support only select, visibility and
  add; there are no groups, masks, multi-selection, clipping or structural undo.
- `DOC-02`: only `normal` blend exists. Save as Canvas and both Whole Canvas / By
  Contour RMB paths are absent rather than merely broken in the new runtime.
- `SAVE-01`: native Open is unused and Save writes only flattened PNG. The dialog
  does not retain the last directory or document path and writes directly to the
  destination rather than temp-plus-atomic-replace.
- `SAVE-02`: preload converts files and bundled brushes to number arrays, causing
  large IPC memory amplification. Full PNG export allocates one full-size
  `OffscreenCanvas` and has no progress/cancel path.
- `PERSIST-01`: autosave clones every allocated tile on the UI thread after each
  edit and has no backpressure, last-good revision, quota status or recovery UI.

Evidence: [`document.ts`](../../../src/contracts/document.ts),
[`raster.ts`](../../../src/contracts/raster.ts),
[`LayerPresenter.ts`](../../../src/ui/layers/LayerPresenter.ts),
[`electron-ipc.mjs`](../../../desktop/electron-ipc.mjs),
[`electron-preload.cjs`](../../../desktop/electron-preload.cjs),
[`renderDocumentPng.ts`](../../../src/core/export/renderDocumentPng.ts),
[`documentSerialization.ts`](../../../src/core/persistence/documentSerialization.ts).

### Brush-library resilience

- `BRH-03`: arbitrary imported `.brush` files are ignored unless they match a
  bundled filename; native presets remain overlays on a bundled base.
- `BRH-04`: Import, Export, Reset, Restore Trash and Reveal Folder are absent;
  active brush selection is not persisted.
- `BRH-05`: first seed uses one `Promise.all`; one missing asset can prevent app
  construction. Bootstrap has no visible error boundary, and a rejected catalog
  load remains cached and cannot recover on retry.

Evidence: [`loadBrushLibrary.ts`](../../../src/core/brush-library/loadBrushLibrary.ts),
[`BrushCatalog.ts`](../../../src/core/brush/BrushCatalog.ts),
[`main.ts`](../../../src/main.ts).

### Architecture and verification truth

- `ARC-01`: documented typed-command/view-model flow is not implemented. UI
  presenters import mutable core document/history/compositor types directly;
  `PointerEvent` leaks into a contract. Existing ESLint rules do not reject it.
- `OPS-01`: `.codex/hooks.json` calls absolute paths in the old `pixelize-tool`;
  the reached hook text contains stale and contradictory policy. Hook docs and
  validators cover only the Claude path.
- `TEST-01`: packaged smoke exits before IPC registration, preload,
  `BrowserWindow`, `dist` or renderer boot. It proves only that Electron starts.
- `TEST-02`: no system test covers pen → RGBA → history → render → autosave;
  `validate:changed` ignores untracked files, and line rules cover only selected
  JS/CSS/config paths.

Evidence: [`layers.md`](../../rule-packs/20-architecture/layers.md),
[`architecture.mjs`](../../../tools/eslint-rules/architecture.mjs),
[`hooks.json`](../../../.codex/hooks.json),
[`electron-main.mjs`](../../../desktop/electron-main.mjs),
[`smoke-packaged-desktop.mjs`](../../../tools/smoke-packaged-desktop.mjs).

## P2: productization and repository drift

- `CFG-01`: `project.config.json` allows 67,108,864 pixels while runtime allows
  50,000,000; there is no parity validator.
- `DEP-01`: current `package-lock.json` coexists with a stale `pnpm-lock.yaml`;
  no canonical package manager or Node engine is declared.
- `DOCS-01`: documentation validation checks shape/links, not exact completion
  commits, traceability or recovery-state agreement; several records say
  `this commit`.
- `WIN-01`: packaging produces only `win-unpacked`; there is no installer,
  product icon/signing/update contract or install/uninstall smoke.
- `SEC-01`: packaged Electron can honor an unrestricted `PRODRAW_DEV_URL`, uses
  prefix matching instead of exact origin and does not validate IPC senders.
- `UI-01`: production contains only Brush/Eraser/Smudge; the other 13 agreed
  commands remain documentation. Text is not misplaced in target runtime—it is
  absent.
- `LEG-01`: the retired pixel editor and 128 legacy tests remain in the tree.
  They are useful only as a parity oracle until R6 and must not be reconnected.
- `UX-01`: some target preset labels and canvas colours bypass i18n/theme tokens;
  accessibility, keyboard map and final touch alternatives remain incomplete.

## Audit conclusion

The correct next move is not to add more toolbar buttons. First make existing
work safe, bounded and truthful: recovery, dirty-tile performance, memory-aware
history, real brush compatibility, honest controls and robust tablet input.
Then build Transform/Liquify and the professional layer/file workflow on those
foundations. The complete delivery order is in
[`07-remediation-plan.md`](07-remediation-plan.md).
